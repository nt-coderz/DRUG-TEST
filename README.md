# ChromaEvidence — Field Drug-Test Evidence App

**Colorimetric Result Capture, Lighting-Calibrated CIELAB / CIEDE2000 ($\Delta E_{00}$) Classification & Tamper-Evident Digitally Signed Evidence Records**

---

## Problem Statement

Field drug-testing kits rely on a human reading a colour change. Results are subjective, differ between officers, and leave no verifiable record that a test happened at a given place and time, so they cannot serve as documentary evidence.

---

## Solution Overview

**ChromaEvidence** is a mobile-first, offline-capable Progressive Web App (PWA) designed to work alongside **existing colorimetric reagent kits** (Marquis, Scott / Cobalt Thiocyanate, Simon's, Duquenois-Levine, Mandelin, Mecke) with **no new hardware required**:

1. **Lighting-Calibrated Camera Capture:** Captures an image of the reagent reaction with the device camera alongside a printable 6-patch D65 Reference Colour Card in frame to normalize ambient illumination (sunlight, tungsten, fluorescent, or vehicle LEDs).
2. **Objective Colorimetric Classification:** Automatically converts calibrated linear RGB into **CIELAB ($L^*, a^*, b^*$)** and computes **CIEDE2000 ($\Delta E_{00}$)** perceptual colour differences against kit-specific reference targets and optical quality gates to classify the outcome as **`POSITIVE`**, **`NEGATIVE`**, or **`INCONCLUSIVE`**.
3. **Tamper-Evident, Digitally Signed Evidence Records:** Generates a canonical JSON record containing UTC/local timestamps, high-accuracy WGS84 GPS coordinates, operator badge/key identity, the **SHA-256 hash of the original untouched camera image bytes**, calibrated analysis metrics, sequential **SHA-256 hash-chain links** (`previousRecordHash` $\rightarrow$ `recordHash`), and a **Web Crypto ECDSA P-256 signature**.
4. **Searchable, Auditable Evidence Log & Geospatial Map:** Maintains a local IndexedDB store with full-chain verification, one-click **signed CSV / JSON audit manifest export**, interactive **Google Maps Platform** pin visualization (with an offline WGS84 coordinate plot fallback), **Firebase Authentication & Cloud Firestore** synchronization, and a **Forensic AI & Grounding Console**.

> **IMPORTANT EVIDENTIARY DISCLAIMER:**  
> All outputs generated by this application are **PRESUMPTIVE field-test screening results** accompanied by a supporting tamper-evident digital record. They do **NOT** replace laboratory confirmatory testing (e.g., GC-MS or LC-MS/MS). This disclaimer is embedded in the capture result view, log detail view, exported JSON/CSV manifests, and printable PDF evidence dossiers.

## Key Features

- **6-Patch D65 Reference Card & Optical Quality Gates:**
  - Printable 100%-scale SVG Reference Card (`Print Card` tab) with 4 corner fiducial markers and 6 known D65 patches (White, 18% Neutral Grey, Carbon Black, Reference Red, Reference Green, Reference Blue).
  - Automatic corner detection & bilinear patch sampling with interactive manual corner/ROI refinement (`RegionPicker`).
  - Von Kries diagonal channel normalization + ridge-regularized $3\times 3$ Colour Correction Matrix (CCM) fitting in linear RGB.
  - 5 automated quality gates: Reference Card Alignment, Dynamic Range / Clipping, Post-Correction Grey Neutrality, Laplacian Sharpness ($\sigma^2$), and Illumination Uniformity.
- **Zero-Dependency Cryptographic Integrity (Web Crypto API):**
  - Non-extractable **ECDSA P-256** private key generated in the browser and stored in IndexedDB; public key JWK and 64-hex SHA-256 fingerprint embedded in every signed record.
  - Deterministic lexicographical **Canonical JSON** (`src/lib/crypto/canonicalJson.ts`) ensures identical SHA-256 digests across platforms.
  - Sequential **SHA-256 Hash Chain** links every test record to its predecessor (`GENESIS_PREVIOUS_HASH` $\rightarrow$ latest head hash), immediately flagging any modified or deleted historical record.
  - Built-in **Tamper Simulation & Independent Verifier** (`Verify Record` tab) to test single-field or single-byte image corruption in real time.
- **Signed CSV & JSON Audit Manifests:**
  - Export the entire Evidence Log as a cryptographically sealed `.json` or RFC-4180 `.csv` manifest signed with the operator's ECDSA P-256 key (`src/lib/crypto/manifest.ts`).
- **Cloud Firestore Sync & Forensic AI Console:**
  - Top-header un-synced record counter and one-click **Sync Now** backup to Cloud Firestore (`/records/{recordId}`) with Google Sign-In.
  - Server-side Gemini Forensic Assistant (`POST /api/gemini/chat`), Google Search Toxicology Grounding (`POST /api/gemini/search-grounding`), and Google Maps Confirmatory Laboratory Locator (`POST /api/gemini/maps-grounding`).

## Tech Stack

- **Frontend:** React 19, TypeScript, Vite 8, Tailwind CSS
- **Colorimetric & Image Engine:** HTML5 Canvas + plain TypeScript (IEC 61966-2-1 sRGB $\leftrightarrow$ CIE XYZ D65 $\leftrightarrow$ CIELAB, Sharma et al. 2005 CIEDE2000 $\Delta E_{00}$)
- **Cryptography:** Browser Web Crypto API (`crypto.subtle` — `SHA-256` & `ECDSA` `P-256`)
- **Local Storage:** IndexedDB via `idb` (untouched original & annotated images stored as binary `Blob`s)
- **Cloud & Geospatial:** Firebase Authentication, Cloud Firestore (with hardened `firestore.rules`), `@vis.gl/react-google-maps` (`AdvancedMarker`, `Pin`, `InfoWindow`)
- **Backend Proxy:** Node.js + Express (`server.ts`) with `@google/genai` SDK
- **PWA:** Web App Manifest (`public/manifest.webmanifest`) + Offline Service Worker (`public/sw.js`)

## Quick Start (How to Run Locally)

### 1. Prerequisites
- **Node.js 20+** and `npm`

### 2. Install Dependencies
```bash
git clone <your-repo-url>
cd DRUG-TEST

# Ensure esbuild matches Vite 8's peer dependency range
npm pkg set devDependencies.esbuild="^0.28.0"

# Install all packages
npm install
```

### 3. Configure Environment Variables (`.env` or `apikeys.env`)
Copy `.env.example` (or your `apikeys.env` file) to `.env` in the project root:
```bash
cp .env.example .env
# Or if your keys are saved in apikeys.env:
cp apikeys.env .env
```
Add your API keys in `.env` (optional for core offline colorimetric capture, ECDSA signing, hash-chain verification, and offline WGS84 coordinate plotting; required for the Forensic AI Console and live Google Maps vector tiles):
```env
GEMINI_API_KEY="your_gemini_api_key_here"
VITE_GOOGLE_MAPS_API_KEY="your_google_maps_api_key_here"
```
*(You can generate a free `GEMINI_API_KEY` at [https://aistudio.google.com/apikey](https://aistudio.google.com/apikey).)*

### 4. Start the Full-Stack Development Server (Port 3000)
```bash
npm run dev
```
Open **[http://localhost:3000](http://localhost:3000)** in your browser.

### 5. Run Unit Tests, Security Rules Linter & Production Build
```bash
# Run the 9 unit tests (CIEDE2000 Sharma benchmark pairs, ECDSA P-256, Hash-Chain & Signed Manifests)
npx tsx --test src/__tests__/colour.test.ts src/__tests__/crypto.test.ts

# Lint Firestore security rules
npx eslint firestore.rules

# TypeScript typecheck
npm run lint

# Build production bundle into dist/
npm run build

# Start production server on http://localhost:3000
NODE_ENV=production npm start
```

## How to Demo in 3 Minutes

1. **Print Reference Card (`Print Card` tab):**  
   View or print the 6-patch D65 Reference Colour Card with 4 corner fiducial markers (White, 18% Neutral Grey, Carbon Black, Red, Green, Blue).
2. **Capture & Calibrate (`New Test` tab):**  
   - Select a colorimetric reagent kit (e.g., *Marquis Reagent* or *Scott Cobalt Thiocyanate Test*), enter a Case Reference, and confirm the reaction wait timer.
   - Click **Continue to Camera & Reference Card Capture**, choose a preset in **Simulate Capture Mode** (including warm tungsten cast, glare/clipping, or borderline $\Delta E_{00}$), or use a live device camera / uploaded photo.
3. **Review Explanation & Optional Override (`Step 3: Review`):**  
   - Inspect the detected reference card patches, RGB illumination gains, calibrated sample CIELAB ($L^*, a^*, b^*$) swatch, and side-by-side candidate reference swatches with **CIEDE2000 ($\Delta E_{00}$)** distances and optical quality gates.
   - Optionally record an **Operator Override** with a mandatory forensic justification (both the automatic classification and the override are preserved in the signed record).
4. **Sign & Append (`Step 4: Sign & Save`):**  
   Sign the canonical JSON digest with the operator's non-extractable **Web Crypto ECDSA P-256** private key and append it to the sequential SHA-256 hash chain.
5. **Tamper Demo & Verification (`Verify Record` tab):**  
   - Select any signed record (or upload an exported `.json` + original `.png` image).
   - Observe all cryptographic checks (`PASS`).
   - Click **Tamper Demo: Flip Result Field** or **Tamper Demo: Flip 1 Image Byte** to see immediate SHA-256 and ECDSA verification failure (`FAIL`), then click **Restore Authentic Record**.
6. **Export Signed Audit Manifest (`Evidence Log` tab):**  
   Click **Export JSON Manifest** or **Export CSV Manifest** to download a cryptographically signed manifest of all stored records for external auditing.

## Calibrating `src/config/kits.json` for Operational Reagent Lots

All CIELAB values shipped in `src/config/kits.json` are marked as **ILLUSTRATIVE PLACEHOLDERS**. To calibrate for an operational reagent lot:
1. Print the Reference Colour Card (`Print Card` tab) at 100% scale on matte archival card stock.
2. React verified control samples for each kit outcome and capture alongside the reference card after `reactionTimeSec` has elapsed.
3. Read the calibrated D65 $L^*, a^*, b^*$ coordinates displayed on the Review explanation panel and update the corresponding entry in `src/config/kits.json`.

## Limitations & Production Hardening Path

1. **Hardware-Backed Key Storage**: In this browser prototype, the non-extractable `CryptoKey` resides in IndexedDB. A production deployment should bind signing keys to hardware security modules (**Apple Secure Enclave** / **Android StrongBox Keystore**) with MDM device attestation.
2. **Trusted Timestamping (RFC 3161)**: Device clocks can drift while offline. Production apps should submit `recordHash` digests to an **RFC 3161 Time-Stamp Authority (TSA)** upon network reconnection.
3. **Server-Side WORM Hash-Chain Anchoring**: Synchronize the local hash chain to an append-only, immutable server ledger (Write-Once-Read-Many) so that clearing browser storage cannot erase an entire local chain.
4. **Enterprise Authentication**: Pair or replace the local PIN stand-in with agency OIDC/SAML and FIDO2/WebAuthn hardware token authentication.
