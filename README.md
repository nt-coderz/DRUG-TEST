# ChromaEvidence — Field Drug-Test Evidence App

**Presumptive Colorimetric Field-Test Capture, CIELAB / CIEDE2000 Lighting-Calibrated Classification & Tamper-Evident Digitally Signed Records**

> **IMPORTANT EVIDENTIARY FRAMING:**  
> All outputs generated by this application are **PRESUMPTIVE field-test screening results** accompanied by a tamper-evident digital audit record. They do **NOT** replace confirmatory forensic laboratory analysis (e.g., GC-MS or LC-MS/MS).

---

## 1. Quick Start & Running Tests

```bash
# Install dependencies
npm install

# Start the development server (http://localhost:3000)
npm run dev

# Run the colour science (Sharma ΔE00) and Web Crypto unit test suites
npx --yes tsx --test src/__tests__/colour.test.ts src/__tests__/crypto.test.ts

# Production build
npm run build
```

## 2. How to Demo in 3 Minutes

1. **Print Reference Card (`Print Card` tab):**  
   View the in-app printable 6-patch D65 Reference Colour Card with 4 corner fiducial markers (White, 18% Neutral Grey, Carbon Black, Red, Green, Blue).
2. **Capture & Calibrate (`New Test` tab):**  
   - Select a colorimetric reagent kit (e.g., *Marquis Reagent* or *Scott Cobalt Thiocyanate Test*), enter a Case Reference, and verify the reaction wait time.
   - Click **Continue to Camera & Reference Card Capture**, then choose a preset in **Simulate Capture Mode** (or use a live camera / uploaded photo) and click **Generate Simulated Capture**.
3. **Review Explanation & Optional Override (`Step 3: Review`):**  
   - Inspect the detected reference card patches, RGB illumination gains, calibrated sample CIELAB ($L^*, a^*, b^*$) swatch, and side-by-side candidate reference swatches with **CIEDE2000 ($\Delta E_{00}$)** distances and optical quality gates.
   - Optionally add an **Operator Override** with a mandatory forensic justification (preserving both the automatic classification and the override).
4. **Sign & Append (`Step 4: Sign & Save`):**  
   Sign the canonical JSON digest with the operator's non-extractable **Web Crypto ECDSA P-256** private key and append it to the SHA-256 hash chain.
5. **Tamper Demo & Verification (`Verify Record` tab):**  
   - Select any signed record (or upload an exported `.json` + original `.png` image).
   - Observe all cryptographic checks (`PASS`).
   - Click **Tamper Demo: Flip Result Field** or **Tamper Demo: Flip 1 Image Byte** to see immediate SHA-256 and ECDSA verification failure (`FAIL`), then click **Restore Authentic Record**.

## 3. Architecture Overview

- **`src/config/kits.json` & `src/config/thresholds.ts`**: Config-driven reagent kit definitions (Marquis, Scott, Simon's, Duquenois-Levine, Mandelin, Mecke) with illustrative CIELAB reference targets, minimum reaction times, and quality/classification thresholds.
- **`src/lib/colour/`**:
  - `srgb.ts` & `lab.ts`: IEC 61966-2-1 sRGB $\leftrightarrow$ Linear RGB $\leftrightarrow$ CIE XYZ (D65) $\leftrightarrow$ CIELAB conversions.
  - `deltaE2000.ts`: Full implementation of the Sharma, Wu & Dalal (2005) CIEDE2000 ($\Delta E_{00}$) colour-difference formula, verified against the 12 benchmark pairs.
  - `calibrate.ts`: Inner-region median pixel sampling, Von Kries diagonal white/grey channel gain in linear RGB, and ridge-regularized $3\times 3$ Colour Correction Matrix (CCM) fitting across all 6 reference patches.
  - `quality.ts` & `cardDetect.ts`: Corner fiducial detection, bilinear patch interpolation, dynamic range exposure checks, post-correction grey neutrality, Laplacian variance sharpness ($\sigma^2$), and left-to-right illumination uniformity.
  - `classify.ts`: Deterministic decision engine evaluating nearest $\Delta E_{00}$, tolerance, separation margin to 2nd-nearest candidate, quality gates, and minimum reaction wait time.
- **`src/lib/crypto/`**:
  - `canonicalJson.ts`: Deterministic lexicographically sorted JSON serialization.
  - `hash.ts`, `keys.ts`, `sign.ts`, `verify.ts`, `chain.ts`: Web Crypto API SHA-256 hashing of untouched original image bytes, non-extractable ECDSA P-256 key generation in IndexedDB, public key JWK SHA-256 fingerprinting, canonical record signing, and full hash-chain integrity verification.

## 4. Calibrating `src/config/kits.json`

All CIELAB values shipped in `src/config/kits.json` are marked as **ILLUSTRATIVE PLACEHOLDERS**. To calibrate for an operational reagent lot:
1. Print the Reference Colour Card (`Print Card` tab) at 100% scale on matte archival card stock.
2. React verified control samples for each kit outcome and capture alongside the reference card after `reactionTimeSec` has elapsed.
3. Read the calibrated D65 $L^*, a^*, b^*$ coordinates displayed on the Review explanation panel and update the corresponding entry in `src/config/kits.json`.

## 5. Limitations & Production Hardening Path

1. **Hardware-Backed Key Storage**: In this browser prototype, the non-extractable `CryptoKey` resides in IndexedDB. A production deployment must bind signing keys to hardware security modules (**Apple Secure Enclave** / **Android StrongBox Keystore**) with MDM device attestation.
2. **Trusted Timestamping (RFC 3161)**: Device timestamps can be skewed if an offline clock is altered. Production apps should submit `recordHash` digests to an **RFC 3161 Time-Stamp Authority (TSA)** upon network reconnection.
3. **Server-Side WORM Hash-Chain Anchoring**: Synchronize the local hash chain to an append-only, immutable server ledger (Write-Once-Read-Many) so that clearing browser storage cannot erase an entire local chain.
4. **Enterprise Authentication**: Replace the prototype PIN stand-in with agency OIDC/SAML and FIDO2/WebAuthn biometric authentication.
